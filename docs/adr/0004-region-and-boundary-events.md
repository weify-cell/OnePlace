# ADR-0004：区域（家/公司）与越界判定

状态：已接受（2026-10-15）

## 背景

现有事件是**由「停留」推导**的：在某处待够 10 分钟才生成到达/离开。这有两个问题：
"到家了"要等 10 分钟后才发；而且地点只有编号或机器查来的名字，不是用户认的那个地方。

用户要的是：**在地图上划定家、公司这类区域的范围**，靠**越界**判定"到家/到公司"，而不是靠"待够多久"。

## 决策

1. **区域 = 有手工名字的地点**（不引入独立概念）。
   - `phone_places.name` 只有用户命名（`name_place` 工具）才会写；高德查来的机器名存在 settings
     的 `phone_place_geo_<id>` 里，**不进 `name`**。因此「`name` 非空 ⇔ 这是用户划定的区域」。
   - 复用现有的圆心 + 半径（`center_lat/center_lon/radius_m`），**零 schema 改动**。
   - 用户也可以从零创建一个区域（新公司、父母家这类还没被自动识别的地点）。
   - 代价：同一处不能定义两个不同范围（可接受）。

2. **判定靠越界 + 驻留 2 分钟**（不用"待够 10 分钟"）。
   - 某个区域的状态分"已确认在内 / 已确认在外"，初始为**未知**；
     第一次稳定观测只**静默确立**状态，不发事件——功能上线时你在家，不该收到"到家了"。
   - 观测与已确认状态矛盾时起算「趋势」，趋势**持续满 2 分钟**才确认切换并发事件；
     趋势中途被推翻则丢弃。对称处理进入与离开，边界抖动不会反复横跳。
   - **事件的时刻是趋势开始的那一刻**（真实到家时间），不是确认时刻——日志里不能把 22:20 记成 22:22。
   - 点是否在区域内：`距离 ≤ radius_m + min(accuracy, 100)`，与停留判定同一个宽容规则（室内定位精度差）。

3. **有名区域不再发旧的"停留到达"**：同一个地点只走一条路径，避免"到家了"和"在某某停留"两条重复通知。
   自动识别但未命名的地点保留原有行为（低打扰）。

4. **形状先只做圆**。家/公司一个 150–300 米的圆足够；多边形绘制是另一个量级的复杂度。

5. **事件与推送复用现有管道**：区域事件写进 `phone_events`（`target_kind='region'`），
   静默时段、时效上限、每日额度、一轮最多一条——全部自动继承。

## 后果

- 区域事件与停留事件**可能同时存在**（在同一次停留上）：到达区域是"刚进门就判定"，停留是"待够 10 分钟"。
  有名区域已按第 3 条屏蔽停留事件；未命名地点只有停留事件。二者互补而非重复。
- `phone_events` 的 `UNIQUE(device_id, event_type, target_kind, target_id)` 会把
  "同一天第二次到家"当重复**静默吞掉**（区域 id 每次都一样）。需要把 `occurred_at` 纳入唯一键。
  这是本功能唯一需要动 schema 的地方（SQLite 无法删除内联 UNIQUE，得重建表）。
- 区域状态存在 `phone_track_state` 里（与切分器状态同一张表、不同 key），保持两个纯函数互不耦合。
- 用户改了区域范围后，已确认的"在内/在外"可能过时；下一批点会按 2 分钟规则自然纠正，无需特殊处理。
